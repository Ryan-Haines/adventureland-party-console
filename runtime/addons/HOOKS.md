## Storage and delivered data

Each add-on's small stores: one model on the character, the coordinator and the dashboard. A store key names whose values they are: `character:<name>` for one character's own, `scope:<owner>` for one farming scope's, and `party` for the whole party. The coordinator holds every store and saves it. A count an add-on keeps on the client, such as a count of deaths, outlives a reload of that client: the character reports its writes with each status, and every reply hands back the keys the coordinator holds newer. Each key carries its own revision and the side that wrote it. A merge keeps the higher revision; on a tie the coordinator's write wins, so a character write and a dashboard write to different keys both survive. A revision is the writer's clock in milliseconds, raised by one past the key's last revision, so a coordinator restart still writes newer than any revision a character holds. A store is never a setting: a write never runs the settings `check` and never changes what the player saved (SV).

An add-on holds its store through `AddonStoreHandle`, and reads what the coordinator delivers to it with `delivered(name)` from addon-api.ts.
